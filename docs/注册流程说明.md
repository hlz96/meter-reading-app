## 1. 概述

本 App 为**多人协作**模式,账号体系围绕「组织 (Organization)」组织。注册分两条路径:

- **路径 A — 管理员自主注册**:第一位使用者注册并创建组织,自动成为管理员;
- **路径 B — 成员受邀加入**:抄表员 / 查看者由管理员邀请,通过邀请链接或邀请码注册加入已有组织。

> 设计原则:组织必须先由管理员创建,成员才能加入;不存在"游离于组织之外"的账号。

---

## 2. 角色与注册方式对照

| 角色 | 如何获得账号 | 是否需要邀请 |
|------|--------------|--------------|
| 管理员 (Admin) | 自主注册并创建组织 | 否 |
| 抄表员 (Reader) | 管理员邀请后注册加入 | 是 |
| 查看者 (Viewer) | 管理员邀请后注册加入 | 是 |

---

## 3. 路径 A:管理员注册(创建组织)

### 3.1 流程步骤
```
下载并打开 App
  → 点击「注册」
  → 选择「创建新组织 / 我是管理员」
  → 输入手机号 / 邮箱
  → 获取并填写验证码
  → 设置登录密码
  → 填写组织信息(组织名称、可选:联系人、行业)
  → 阅读并同意《用户协议》《隐私政策》
  → 提交 → 注册成功,进入管理员首页
```

### 3.2 步骤详述
1. **进入注册页**:首次打开 App,在登录页点击「注册」。
2. **选择注册类型**:选择「创建新组织」(即以管理员身份注册)。
3. **填写账号标识**:输入手机号或邮箱作为登录账号。
4. **验证身份**:接收短信 / 邮件验证码,填写完成校验。
5. **设置密码**:按密码强度要求设置登录密码。
6. **创建组织**:填写组织名称等基础信息,该组织即成为后续所有公司、表计、成员的归属。
7. **同意协议**:勾选同意用户协议与隐私政策。
8. **完成**:注册成功,自动登录并成为该组织管理员。

---

## 4. 路径 B:成员受邀加入

### 4.1 前置条件
管理员已在 App 内的「成员管理」中发起邀请,生成**邀请链接**或**邀请码**,并指定了受邀人的角色(抄表员 / 查看者)。

### 4.2 流程步骤
```
收到邀请链接 / 邀请码
  → 打开 App(未安装则先下载)
  → 点击「加入组织 / 我有邀请码」或直接点邀请链接
  → 校验邀请(展示将加入的组织名称、被分配的角色)
  → 输入手机号 / 邮箱 + 验证码
  → 设置登录密码
  → 同意协议
  → 提交 → 加入成功,以对应角色进入组织
```

### 4.3 步骤详述
1. **接收邀请**:通过微信 / 短信 / 邮件收到管理员发来的邀请链接或邀请码。
2. **发起加入**:
   - 点邀请链接:App 自动带出邀请信息;
   - 或手动在注册页选「加入组织」并输入邀请码。
3. **确认组织与角色**:页面展示「你将加入 XX 组织,角色为 抄表员」,确认无误后继续。
4. **填写账号并验证**:输入手机号 / 邮箱,完成验证码校验。
5. **设置密码 + 同意协议**。
6. **完成**:加入成功,按管理员分配的角色进入,权限即时生效。

---

## 5. 关键规则与边界

| 规则 | 说明 |
|------|------|
| 账号唯一性 | 同一手机号 / 邮箱在同一组织内不可重复注册 |
| 邀请有效期 | 邀请链接 / 邀请码建议设有效期(如 7 天)与可失效机制 |
| 已注册用户受邀 | 若受邀人已有账号,则走「加入组织」而非重新注册(直接绑定到新组织角色) |
| 角色变更 | 注册后角色由管理员在「成员管理」中调整,用户自身不能改角色 |
| 找回密码 | 通过注册手机号 / 邮箱验证码重置 |

---

## 6. 异常与提示

| 场景 | 系统提示 |
|------|----------|
| 验证码错误 / 过期 | "验证码有误或已过期,请重新获取" |
| 手机号已注册 | "该手机号已注册,请直接登录或找回密码" |
| 邀请码无效 / 过期 | "邀请已失效,请联系管理员重新发送" |
| 密码强度不足 | "密码需 8-20 位,含字母和数字" |

## 7. 待确认问题

1. 账号标识用**手机号**、**邮箱**还是两者都支持?是否支持微信 / 第三方一键登录?
2. 是否允许一个用户加入**多个组织**(未来多组织场景)?本期是否先限制为单组织?
3. 邀请方式优先做**邀请链接**还是**邀请码**,还是两者都要?
4. 是否需要管理员对成员注册做**二次审核**(申请加入 → 管理员通过)?
5. 验证码渠道(短信 / 邮件)与服务商是否已确定?涉及成本与合规。

> 以上确认后可细化为交互原型与接口设计。
