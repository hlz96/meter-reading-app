## 1. 概述

本 App 为 iOS / Android 双端原生应用。从"开发完成"到"用户能下载",需经过 **打包构建 → 渠道上架 → 用户下载安装** 三大环节。iOS 与 Android 的发布路径差异较大,下面分端说明,并给出「正式上架」与「内测分发」两条路线。

```
开发完成
  ├── iOS   → App Store Connect 上架 / TestFlight 内测
  └── Android → 各应用商店上架 / APK 直接分发 / 内测平台
        ↓
     用户搜索或扫码 → 下载安装 → 打开注册使用
```

## 2. 发布前准备(双端通用)

| 事项 | 说明 |
|------|------|
| App 名称与包名 | 确定应用名、iOS Bundle ID、Android 包名(上架后不可随意更改) |
| 图标与启动图 | 各尺寸 App 图标、启动页 |
| 应用截图与介绍 | 商店展示用截图、一句话简介、详细描述、关键词 |
| 版本号 | 语义化版本(如 1.0.0)+ 构建号 |
| 隐私合规材料 | 隐私政策链接、《个人信息收集清单》、权限使用说明 |
| 备案(国内必需) | Android 上架国内商店、iOS 上架中国区,均需 App 软件著作权 / ICP 备案等资质 |

> ⚠️ **国内合规提醒**:2023 年后国内安卓应用商店与 iOS 中国区上架均要求 App 完成工信部备案,需预留备案周期(通常 1–2 周)。

## 3. iOS 发布流程

### 3.1 正式上架 App Store
```
注册 Apple Developer 账号(个人/公司,$99/年)
  → 在 App Store Connect 创建 App 记录
  → 配置证书、描述文件、签名
  → Xcode / CI 打包上传构建版本
  → 填写商店信息(截图、描述、分级、隐私问卷)
  → 提交审核 → Apple 审核(通常 1–3 天)
  → 审核通过 → 发布上线(可手动/定时)
```

### 3.2 内测分发(TestFlight)
- 上传构建版本后,通过 **TestFlight** 邀请内测用户(邮箱或公开链接)。
- 内测最多 10000 人,无需正式审核即可快速验证,适合上架前试用。

### 3.3 关键点
- 必须有 **Apple 开发者账号**(公司账号需邓白氏编码 DUNS);
- iOS 无法像安卓一样直接发 APK 给普通用户安装(除企业开发者账号做内部分发);
- 中国区上架需备案资质。

---

## 4. Android 发布流程

Android 生态开放,分发渠道多,可组合使用。

### 4.1 应用商店上架(推荐,覆盖面广)
国内主流:**华为、小米、OPPO、vivo、应用宝(腾讯)** 等各商店需分别注册开发者、分别提交审核。
```
注册各商店开发者账号(需企业资质 + App 软著/备案)
  → 上传签名后的 APK / AAB
  → 填写商店信息与截图
  → 提交审核(各商店 1–3 天不等)
  → 审核通过 → 上架
```
> 海外可选 **Google Play**(注册费 $25 一次性),国内用户一般不用。

### 4.2 APK 直接分发(最快,适合小范围)
- 直接把签名后的 `.apk` 文件通过网页 / 二维码 / 网盘发给用户;
- 用户下载后需在手机「设置」中允许「安装未知来源应用」;
- 优点:无需审核、即时可用;缺点:用户信任度低、无自动更新、部分机型拦截。

### 4.3 内测分发平台(推荐用于测试阶段)
- 使用 **蒲公英 (pgyer)**、**fir.im** 等第三方内测平台;
- 上传 APK 后生成下载二维码 / 短链,支持 iOS + Android 混合分发、版本管理、安装统计;
- 适合 App 未正式上架前,给公司内部人员试用。

### 4.4 关键点
- Android 必须用**发布签名(keystore)**签名,**签名文件务必妥善备份**——丢失后无法给已上架应用发更新;
- 上架国内商店需企业营业执照 + App 软著。

## 5. 分发路线选择建议

| 阶段 | iOS | Android | 说明 |
|------|-----|---------|------|
| **开发/内测** | TestFlight | 蒲公英 / APK 直发 | 快速迭代,无需审核 |
| **小范围试点** | TestFlight | APK 二维码 / 蒲公英 | 给试点客户用 |
| **正式发布** | App Store | 华为/小米/应用宝等主流商店 | 面向公开用户 |

> 建议路径:先用 **TestFlight + 蒲公英** 做内测跑通闭环,验证后再走正式上架,避免过早陷入备案与审核周期。

## 6. 用户下载安装流程(面向最终用户)

### iOS 用户
```
App Store 搜索「(应用名)」→ 点击「获取」→ 面容/指纹确认 → 安装 → 打开
```
或(内测):收到 TestFlight 邀请 → 装 TestFlight → 点邀请链接 → 安装。

### Android 用户
```
方式一:应用商店搜索「(应用名)」→ 安装
方式二:扫下载二维码 / 点链接 → 下载 APK → 允许未知来源 → 安装
```

安装后即进入 **App 账号注册流程**(详见《注册流程说明.md》)。

## 7. 版本更新与维护

| 事项 | 说明 |
|------|------|
| 版本迭代 | 每次更新递增版本号与构建号,重新打包上传、提交审核 |
| 强制更新 | 建议在 App 内做版本检测,重大更新可提示/强制升级 |
| 灰度发布 | 商店多支持分阶段放量(如先 10% 用户),降低风险 |
| 崩溃监控 | 接入崩溃/性能监控,发布后关注线上稳定性 |
