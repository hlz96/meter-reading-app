## 1. 背景与目标

### 1.1 背景
物业/园区/房东在管理多家入驻公司时,需要定期抄录每家公司的水表、电表读数,核算用量并催缴费用。目前多依赖纸质记录或零散的 Excel 表格,存在以下痛点:

- 抄表数据分散,底数与本期读数容易记错、漏抄;
- 按公司归集用量、生成催缴单靠人工统计,费时且易错;
- 缺少历史趋势视图,无法直观看出某家公司用量异常。

### 1.2 产品目标
打造一款面向多人协作的移动抄表管理工具,实现:

1. **表计台账管理** — 在线编辑或批量导入水表、电表的名称、所属公司、底数、本期读数等信息;
2. **按公司分组催单** — 依据表计所属公司自动归集为子表,支持一键生成催缴清单;
3. **用量汇总分析** — 以表格 + 图表形式呈现每家公司的用水/用电情况。

### 1.3 成功衡量指标 (北极星)
- 单次抄表录入耗时较纸质/Excel 下降 ≥ 50%;
- 月度用量统计报表生成时间从「小时级」降至「分钟级」;
- 抄表数据错误率(需事后修正的记录占比)< 2%。

## 2. 用户与角色

### 2.1 目标用户
物业管理公司、产业园区运营方、二房东 / 商业楼宇管理者等需要对多个租户分表计量的场景。

### 2.2 角色与权限
| 角色 | 职责 | 核心权限 |
|------|------|----------|
| **管理员 (Admin)** | 系统与组织管理者 | 全部权限:成员管理、公司/表计增删改、导入导出、查看所有报表 |
| **抄表员 (Reader)** | 现场抄录读数 | 查看分配给自己的表计、录入本期读数、上传照片;不可删除表计、不可管理成员 |
| **查看者 (Viewer)** | 只读汇报对象(如财务) | 查看报表与汇总,导出数据;不可编辑任何数据 |

> 权限模型采用「组织 (Organization) → 成员 → 角色」结构,一个组织下可有多名成员,后续可扩展为多组织。

## 3. 核心概念与数据模型

### 3.1 领域实体
| 实体 | 说明 | 关键字段 |
|------|------|----------|
| **公司 (Company)** | 表计的归属租户 | 公司名称、联系人、联系电话、备注 |
| **表计 (Meter)** | 一块水表或电表 | 表计名称/编号、类型(水表/电表)、所属公司、初始底数、倍率、安装位置、状态(启用/停用) |
| **抄表记录 (Reading)** | 一次抄表的读数快照 | 关联表计、抄表周期、上期读数、本期读数、用量(自动计算)、抄表人、抄表时间、照片、备注 |
| **抄表周期 (Period)** | 一个统计区间(如 2026-08) | 周期名称、起止日期、状态(进行中/已结算) |

### 3.2 关键计算规则
- **本期用量 = (本期读数 − 上期读数) × 倍率**
- 上期读数默认取该表计上一周期的本期读数;首次抄表时取「初始底数」。
- 若本期读数 < 上期读数,系统提示「可能表计翻转或抄错」,需人工确认(支持记录翻转量)。
- 公司用量 = 该公司下所有同类型表计用量之和,水/电分别汇总。

## 4. 功能需求

### 4.1 功能地图
```
水电表抄表管理 App
├── 账号与组织
│   ├── 注册 / 登录
│   ├── 成员邀请与角色分配
│   └── 组织信息设置
├── 台账管理
│   ├── 公司管理(增删改查)
│   ├── 表计管理(在线编辑)
│   └── 批量导入 / 导出(Excel)
├── 抄表作业
│   ├── 按公司/周期筛选待抄表计
│   ├── 录入本期读数 + 拍照
│   └── 异常校验(读数倒退提示)
├── 催单管理
│   ├── 按公司自动归集子表
│   └── 生成 / 导出催缴清单
└── 汇总分析
    ├── 各公司用量报表(表格)
    └── 用量趋势 / 占比图表
```

### 4.2 功能详述

#### FR-1 台账:表计在线编辑
- 支持新增/编辑表计:名称、类型、所属公司、初始底数、倍率、位置、状态。
- 列表支持按公司、类型、状态筛选与搜索。
- **优先级:P0**

#### FR-2 台账:批量导入 / 导出
- **可配置导入模板**:系统不硬编码 Excel 列,而是提供「模板配置」机制——
  - 内置一份默认模板(含公司、表计名、类型、底数、倍率等常用列)供下载;
  - 支持自定义模板:管理员可配置「Excel 表头 ↔ 系统字段」的映射关系、哪些列必填、列的顺序与别名;
  - 导入时按所选模板解析,允许保存多套模板以适配不同来源的表格。
  - > 具体默认字段集以后续提供的实际模板为准,当前保持字段映射可配置、不写死。
- 导入时做字段校验,错误行高亮并给出原因,支持「仅导入正确行」或「全部回滚」。
- 支持导出当前台账与抄表记录为 Excel。
- **优先级:P0**

#### FR-3 抄表:读数录入
- 抄表员按周期看到待抄清单(可按公司分组)。
- 录入本期读数,系统实时显示计算出的用量;可拍照留证、加备注。
- 读数倒退 / 用量异常(超过历史均值 N 倍)时给出提示。
- **优先级:P0**

#### FR-4 催单:按公司分组子表
- 依据表计所属公司,自动将表计与用量归集为「公司子表」。
- 每家公司生成一张催缴清单:含各表用量、合计水费/电费(费率可配置)、抄表周期。
- 支持导出为图片/Excel/PDF,便于发送给对应公司。
- **优先级:P1**

#### FR-5 汇总:表格化统计
- 按周期展示所有公司的用水量、用电量、费用合计,支持排序与导出。
- **优先级:P0**

#### FR-6 汇总:图形化分析
- 提供:各公司用量占比(饼图)、单公司用量趋势(折线图)、周期对比(柱状图)。
- **优先级:P1**

#### FR-7 账号与组织
- 手机号/邮箱注册登录;管理员邀请成员并分配角色;基础的组织信息维护。
- **优先级:P0**(权限是多人协作前提)

### 4.3 需求优先级汇总
| 编号 | 功能 | 优先级 |
|------|------|--------|
| FR-1 | 表计在线编辑 | P0 |
| FR-2 | 批量导入/导出 | P0 |
| FR-3 | 读数录入 | P0 |

## 5. 关键业务流程

### 5.1 抄表主流程
```
选择抄表周期 → 筛选公司/表计 → 逐表录入本期读数
   → 系统自动算用量 & 异常校验 → (可选)拍照+备注
   → 提交保存 → 周期内数据可随时补录/修正
```

### 5.2 月度结算与催单流程
```
周期抄表完成 → 按公司归集用量 → 应用费率算费用
   → 生成各公司催缴子表 → 导出/分享给公司 → 标记周期为「已结算」
```

## 6. 非功能性需求

| 类别 | 要求 |
|------|------|
| 离线能力 | 现场抄表可能无网络,录入需支持离线暂存,联网后自动同步 |
| 性能 | 单组织 ≤ 5000 块表计时,列表与汇总响应 < 2s |
| 数据安全 | 账号密码加密存储;按角色做数据访问控制;操作留痕(谁在何时改了读数) |
| 兼容性 | iOS 14+ / Android 10+ |
| 可用性 | 现场单手操作友好,核心录入路径 ≤ 3 次点击 |

---

## 7. 范围边界 (本期不做)

- 与电力/水务公司官方系统对接、自动读数(需硬件/IoT,后续规划);
- 在线支付 / 收款对账(仅生成催缴单,不做资金流);
- 多组织 SaaS 化、跨组织数据隔离的完整方案(先支持单组织多成员);
- 复杂阶梯费率、税费计算(先支持单一费率,可配置)。

## 9. 待确认问题 (Open Questions)

1. 费率是全组织统一,还是每家公司/每类表可单独设置?
2. 抄表周期是固定按自然月,还是允许自定义起止日期?
3. 催缴单是否需要固定模板/加盖公司抬头?导出格式优先 Excel 还是 PDF/图片?
4. 是否需要「审核」环节(抄表员提交 → 管理员确认后才算数)?
5. 离线同步的冲突处理策略(同一表被两人先后录入)如何取舍?

> 以上问题建议在需求评审时逐条确认,确认后进入 HLD(概要设计)阶段。
